# 仓库空间分析与瘦身策略

本报告依据用户提供的目录占用截图、2026-10-17现场元数据扫描、局部内容摘要比对和项目存储约定。**仅分析和出具报告；没有删除、搬移、压缩、修改配置、提交或推送。已有18项暂存内容保持原样，本轮仅新增本报告，并按文档规范在索引中补一行导航，未暂存这些新增内容。**

## 结论

工作区约 **17.58 GiB**，主要是本机构建与离线资产；当前Git索引内现存普通文件仅 **9.66 MiB**，仓库根 `.git/` 约 **27.62 MiB**。清理被忽略的构建目录能减少本机磁盘占用，基本不会减少GitHub克隆体积。不要为解决17.58 GiB本地占用而优先改写Git历史。

优先处理已确认可重建的合成夹具，随后处理废弃Android构建分支和历史图谱备份。**不要整删app、build_fp15_gtest、cache、deps、web/node_modules或models。**

- 确认23个50MiB+1字节的合成oversize夹具，合计 **1,150.00 MiB**，内容摘要相同；它们在Windows构建树中，与此前已删除的cache A1是不同文件，不能混同或重复计入已完成收益。
- Android存在ncnn关闭/开启两套各约2 GiB的真实OpenCV构建；旧分支与旧式打包中间目录是主要后续候选，需先保全构建绑定与负向回归证据。
- 图谱有22个日期备份；若认可保留最近2份，旧20份的候选大小为 **272.88 MiB**。此保留周期是建议，未获得执行授权。
- Cypress存在约 **602.73 MiB** 的附加副本；此前明确要求保留，且原树中有实际接收端使用的FFmpeg，暂不计入可直接清理量。

本报告不含删除授权。后续按阶段单独执行：确认无使用者；逐个列规范绝对路径、字节、mtime与SHA256；检查目标和祖先无重解析点；冻结清单并先演练越界/漂移/占用拒绝；遇到变化或错误整批停止。删除按字面路径逐文件执行，目录只在已验证为空时移除，不提权强删，不展开到父目录。

迁移先验证配置与消费者，再删除旧副本；有绝对路径的构建树采用重新配置/重建，不直接挪动。不为了清理而访问实机、重跑全部CI、执行外网推流或修改模型预处理。

完成标准：只批准目标消失；源码、许可、父模型、AAR、必需消费路径和唯一证据仍可核验；Git暂存区不受影响；报告真实逻辑删除量与卷读数，不混算候选收益。需要逐字节回退的资产，先由用户指定独立备份位置并验证摘要；“可重新编译”不等于“原件可恢复”。
