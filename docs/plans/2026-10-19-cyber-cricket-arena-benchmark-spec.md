# rk3288_opencv 赛博斗蛐蛐：AI 代码修复竞技靶场可行性与题目候选评估（v2.1）

本文是靶场方案，不表示裁判器已经实现，也不表示下列候选故障存在于当前主线。当前结论：本仓库有多语言、多平台代码与测试，可作为题库素材；现有 CI 和测试不是竞技裁判器，尚需固定题目基线、隔离隐藏测试、定义运行预算和评分办法后才能开展公平评测。

## 1. 研究背景与证据边界

Wan 等人 2025 年的研究在其特定任务中观察到链式思维可能受确认偏差影响，但不能据此推断某个当前模型会在 20K–60K token 推理预算下发生特定行为，也不能推断它必然在前两轮失败。另一项 2026 年预印本使用 30 个情境、六类认知偏差和四个模型系列，请求的推理预算上限为 8,192 tokens；它没有验证本方案所列模型、20K–60K 预算或代码修复轮数结论。[Wan 等人，2025](https://arxiv.org/abs/2506.12301)；[The Long Road to the Same Answer，2026 年预印本](https://arxiv.org/abs/2610.10049)

因此，本方案不预设模型失效机制或成功率。模型对比时须记录实际模型/API 版本、推理档位、提示词、工具与权限、上下文和调用预算、依赖环境及每题多次试验结果。模型列表和通过率只应写入带日期的实测报告，不作为长期固定的事实。

## 2. 建议的难度分级

段位描述题目需要解决的问题结构，不预设轮数和通过率。通过率须由固定评测协议下的试跑得出。

| 段位 | 建议判据 | 典型验证方式 |
|---|---|---|
| 青铜 | 单函数或单模块边界条件，失败稳定且定位范围明确 | 确定性单元测试 |
| 白银 | 配置、数据映射或接口约定跨一个模块边界 | 单测加调用方回归 |
| 黄金 | 条件编译、依赖接线或两个构建配置间行为不同 | 对应配置矩阵构建与测试 |
| 铂金 | JNI、异步回调、资源生命周期或多线程状态提交 | 生命周期重复测试与竞态控制测试 |
| 钻石 | 安全边界、并发、网络或多个模块交互，需区分表象与根因 | 可控故障注入、超时守卫及安全回归 |
| 王者 | 多个根因存在可证明的因果耦合；局部修复会暴露或改变其他失败，需跨子系统完成一致修复 | 多故障组合测试、隐藏验收集、重复运行与独立复核 |

以上是本方案建议的内部判据，不是外部竞赛标准。文件数、缺陷数量、代码行数或单纯的严重程度都不能单独决定段位。

## 3. 王者候选案例核验

以下核验针对 2026-10-19 仓库源码快照。表中“当前证据”说明现有代码能支持什么；“建议级别”只是候选定位，必须先实现故障注入并通过可复现性验收，不能当作模型成绩。

| 编号 | 原候选 | 当前证据与表述修正 | 建议级别及入题条件 |
|---|---|---|---|
| P1 | CMake/CRT 堆破坏 | `CMakeLists.txt` 确实为 MSVC 设置静态 CRT `/MT`；这本身不等于跨堆释放。项目记录的 `/MT` 与 `/MD` ncnn 预编译件问题表现为链接不兼容，不能据此声称静默堆破坏。 | **铂金候选**。需构造真实 DLL/模块边界和跨边界所有权错误，附可重复的失败测试；不能只改 CRT 标志。 |
| P2 | 头文件 ABI 错位 | 所述 `FaceRecognition.h` 不在当前源码树中，故现有路径和缺陷描述不成立。 | **黄金候选**。改用当前实际公共结构体，说明 ABI 消费者与字段布局，并以 `sizeof`、`alignof` 或跨模块序列化测试复现。 |
| P3 | JNI 全局引用泄漏 | `native_face_bridge.cpp` 的采集启动路径将 `NewGlobalRef` 存入生命周期槽，失败分支回收；停止采集等待在途回调后调用 `DeleteGlobalRef`。当前证据不支持“异步通知未释放”的概括。 | **铂金候选**。先找到会绕过槽登记或停止清理的真实异常/重复启动路径，再用循环启停和 JNI 引用/内存观测验证。 |
| P4 | HTTP 服务 AB-BA 锁反转 | `HttpFacesServer.cpp` 中未找到所述 `sessionMutex_`、`logMutex_`；当前描述没有可核验的锁序。 | **钻石候选**。必须指定真实锁、两条相反锁序、并发触发条件，并用屏障控制测试稳定复现；否则不列为题目。 |
| P5 | `WSAEWOULDBLOCK` 被误判断开 | 该符号在 CivetWeb 第三方快照中出现；项目指南说明 CivetWeb 未编入当前服务，Windows 服务使用自研 Winsock `HttpFacesServer`。原文把第三方实现行为归给了本项目服务。 | **黄金候选**。若目标是自研服务，先证明其采用非阻塞发送，再注入背压并验证部分发送、重试和断连行为。 |
| P6 | 相机掉线丢失唤醒 | `FramePipeline.cpp` 的相机状态通知使用 `cameraSignalCv_.notify_all()`；`notify_one()` 用于帧队列 `frameCv_`，不能据此断言相机掉线只唤醒一个线程。 | **黄金／铂金候选**。须指明实际等待者、谓词和状态转移；以可控调度测试证明通知遗漏会留下仍需唤醒的线程。 |
| P7 | 符号链接 TOCTOU 导致 HTTP 504 | 测试中不能创建 symlink 时会 `GTEST_SKIP`，这不是 HTTP 504。检查与打开之间的路径替换属于可独立研究的安全场景，但原文混淆了测试环境缺权限与服务端响应。 | **钻石候选**。为路径校验与文件打开之间设置确定性同步点，测试越界读取确实被拒绝；记录 Windows symlink 权限前提，跳过不能算通过。 |
| P8 | 实时管线无锁环形缓冲区 ABA | `RealtimeFacePipeline` 当前以 `shared_ptr<const RealtimePipelineSnapshot>` 配合原子 load/store 发布快照；未发现原文所称环形缓冲区。 | **按现状不入题**。若保留，须明确这是新设计的故障注入而非当前缺陷，并证明引入该结构与题目目标相关；否则换成当前代码中有证据的并发问题。 |
| P9 | 相机重载故障广播导致无限递归 | 当前 `FramePipeline::reloadRuntime()` 在发布回调重入时有 `publishingPipeline == this` 守卫并返回失败；未找到原文所称递归链。 | **暂不定级**。需给出实际回调链、递归入口和确定性复现；没有这些证据前删除“栈溢出”断言。 |
| P10 | 配置迁移失败后重试次数/超时静默归零 | `WinJsonConfig.cpp` 的有界重试用于密钥轮换期间的配置代次冲突；该逻辑不是解析失败后将重试和超时归零。 | **白银／黄金候选**。如题目关注配置迁移，应指定字段、旧新 schema、错误输入和预期保留/拒绝策略，并用迁移回归测试复现。 |

### 王者复合题结论

**当前 P1–P10 不足以支撑“十重全链路强耦合王者题”。** 多项描述与现有源码不符，剩余条目也只是并列的故障类型，没有展示它们之间的因果边。跨四个子系统或修改八个文件只是范围大，不等于强耦合；十个独立缺陷的数量也不等于王者难度。

建议只有在以下条件全部满足后，才将复合题标为“王者候选”：

1. 每个注入根因都能在固定基线上独立复现，并有对应失败测试和恢复验证。
2. 提供缺陷依赖图，至少有两个经测试证明的交互：修复一个根因会改变另一个根因的可见失败或正确修复路径。
3. 复合测试能稳定区分局部绕过与完整修复；不依赖随机竞态、未记录的系统权限或不受控外部服务。
4. 在干净环境完成全量回归和多次试跑后，再以实测通过率描述难度。

未满足条件的单项应按其可验证的实际范围单独分级，不为了凑齐“十重”而强行耦合。

## 4. 轮次与成功率的测量

原文中的“首两轮必败”“至少三轮”以及各段位通过率没有给出实验数据，且“2 轮内必死”与“至少需要 3 轮以上”互相矛盾，现删除这些结果性表述。

试跑前须定义“一轮”是一次完整模型会话、一次补丁提交，还是一次重置后的独立尝试；同时固定工具调用额度、时间上限、是否允许联网、失败后是否保留上下文。每个模型/题目组合应多次独立运行并报告分子、分母、配置和置信区间。没有这些信息时只可写“难度假设”，不得写通过率或必败结论。

## 5. 自动化裁判设计

1. **固定基线**：每题记录仓库提交 SHA、题目注入补丁、依赖锁文件、构建命令、目标平台和所需数据的版本/哈希。
2. **隔离工作区**：每次尝试从固定基线创建临时 worktree 或容器。不要运行 `git checkout HEAD -- tests/`；该命令可能覆盖参赛者未提交的回归测试，也不能证明裁判测试未被修改。
3. **隔离裁判测试**：参赛者可在工作区新增回归测试，但评分使用工作区外、只读挂载的裁判测试包；执行前后校验测试包哈希。公开测试与隐藏测试分开管理。
4. **受控执行**：记录编译器、SDK、依赖、环境变量、CPU/内存/时间限制和网络策略；候选代码在无敏感凭据的隔离环境运行。
5. **准确统计**：分别报告通过、失败、跳过和未运行。必需测试被跳过或依赖缺失时应标为“无法验收”，不能折算为通过；按目标平台声明测试矩阵。
6. **按行为评分**：以构建结果、目标失败复现、隐藏回归测试、跨平台回归和补丁审查组成评分。删除“每次代码修改不得超过对应源文件 15%”的硬限制；行数不能代表修复质量，确需限制时应为单题设定并说明理由。

## 6. 开赛前验收清单

- 题目基线、注入补丁和预期行为可从干净副本重建。
- 每个缺陷有稳定的失败测试；每个“耦合”有单独的交互测试证据。
- 隐藏测试不在候选可写目录中，候选不能修改裁判器或测试清单。
- 全部通过/失败/跳过状态可追溯，依赖或平台缺失不会产生虚假通过。
- 先完成小规模模型试跑，再发布段位、轮数与通过率结论。
