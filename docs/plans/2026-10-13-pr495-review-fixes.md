## 复核循环

首轮独立复核发现两项 INT8 闭环遗漏：FP32 profile 清除显式要求、ncnn 整数 key 的前导零/正号绕过。阈值测试同时补上真实 0.40 分数的决策断言。

补测后真实 ncnn 回归出现 2 项失败，再修改 profile 合并规则和参数解析。参数校验同时限定声明层数、遇非参数停止；真实 FP32 反例先确认普通请求能够推理，并递增模型版本强制重新加载，避免缓存掩盖格式错误。新增四项变异均失败，还原后每次 5/5 通过。

最后由未参与 C++/UI 实现的复核代理检查最终生产代码、测试和第二轮变异证据，未发现新增可执行问题。缺表/旧版/不完整注册表仍只读，保留既有完整 FREG2 安全门禁。

## 环境限制与反思

Web E2E 未能运行：缺失的 Cypress 13.17.0 已从官方下载安装包，CRC 校验和完整解压通过，但 Windows 可执行文件在启动烟测时以 2147483651（0x80000003）崩溃，尚未进入用例。该检查在仓库 CI 中为非阻断；不能将其记为通过。

Android 标准 ncnn 包导出的 -fno-rtti / -fno-exceptions 与本仓既有 C++ 代码冲突；本机验证通过显式 ncnn_DIR 和缓存内临时导入选项适配启用后端，不修改项目或 SDK 配置。此验证不等于标准 Gradle ncnn 构建已闭环。编译还发现 MobileFaceNetAdapter 缺少 thread 头文件，已补一行包含；这是原九项之外、由同一 INT8 编译检查发现的必要修复。

范围是九项发现、相关复核遗漏和一处必要的头文件包含，未增加依赖或放宽注册表安全门。关键修正是让测试验证真实决策/加载行为，而非仅检查字段；可改进点是让本机 Cypress 启动条件与 CI 环境保持一致。本次没有 RK3288 真机精度或性能验收。
