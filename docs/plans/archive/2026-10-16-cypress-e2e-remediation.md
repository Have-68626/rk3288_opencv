# Cypress 启动与覆盖率整改

本专项已结束，下述数字及失败/通过边界保留为该轮快照；当前复现步骤见[构建与测试](../../guides/build-and-test.md#cypress-e2e与覆盖率)，不把历史覆盖率作为当前HEAD结果。

本轮接收侧边会话四份未提交改动，保留心跳、用例事件与退出码传递；用户要求补齐 E2E，按原覆盖率门槛验收，不提交、不推送。

## 根因与最短修复

- Cypress 内部的 Windows PowerShell 查询继承 `CLAUDE_DESKTOP_USE_PWSH=1`，触发本机 profile 启动交互 pwsh，停在 `before:run` 之前。启动器仅从子进程环境副本移除此标记，不改宿主环境或 profile。
- headless 覆盖率插件会合并 `.nyc_output/out.json` 旧计数。启动器每轮将该文件归档至 `cache/web-e2e/<时间戳>-<PID>/out.json`，避免跨轮假通过；保留 Cypress 缓存。
- 启动页“重试”成功后没有导航，现按启动页偏好进入页面。
- HTTP 200 的失败信封曾写入缓存，旧失败缓存也可命中，导致立即重试仍失败。现在只缓存成功信封，忽略旧失败缓存后重新请求。

## 验证

E2E 从原2项扩充至34项，覆盖设置最小补丁、地址脱敏与校验、保存失败重试、启动恢复、模型状态与重载、降级横幅、鉴权头、本地偏好、HTTP 错误、缓存失效及错误边界。所有 API 都由 intercept 隔离，未声明的端点返回合成503；轮换等动作不触达真实后端。

覆盖率按现有 nyc 配置及本轮实际加载的模块统计，**不代表所有懒加载页面、真实 Windows 后端、设备或真人精度验收**。没有降低门槛、改变统计范围或注入覆盖率计数。关闭 HMR 候选经干净运行证伪，未应用；早期合并旧数据的候选通过结果作废。

精准变异共5组：恢复宿主标记继承、不移动旧覆盖率、恢复失败信封缓存写入、允许旧失败缓存命中、移除启动重试导航。前4组在缓存源码副本运行，每组由对应断言检出（1失败、29通过）；第5组仅由临时 Vite 转换插件变异，E2E 对应导航断言失败（1失败、33通过），覆盖率门禁仍通过。生产源码未被变异覆盖。

初次变异受沙箱临时目录 rename 权限影响，不能算检出；改用仓库缓存临时目录后复验。缓存写入变异最初存活，补充“失败信封不落盘、恢复后才缓存成功结果”断言后检出。

本机脱敏日志、阶段事件、30秒进程树心跳和清理结果位于 `cache/audit-fixes-2026-10-13/cypress-main-resume/`，正式验收为 `formal-expanded-round5/` 与变异后的 `formal-final/`；变异证据位于 `mutations/` 与 `splash-mutant-round1/`。日志只在脱敏后落盘；诊断器只终止本次自启进程树，检查5173端口释放。早期超时与失败记录保留，不冒充通过。

## 交付边界与回滚

Windows 静态 webroot 已重新构建。保留侧边会话改动、既存未跟踪 `pt`、复制的 Cypress 缓存及原二进制缓存；本轮不暂存、不提交、不推送。撤销本轮时须按差异撤销启动器、HTTP 与启动页的对应修复，并配套重建 webroot，不得重置侧边会话改动。

反思：边界按用户选择扩展为原门槛达标。关键问题是宿主交互标记及跨轮计数污染；应先隔离环境和统计，再依据真实界面断言与变异检验测试质量。
