# 本地测试套件统一调度与汇总设计

本设计已获用户批准，按[实施计划](../plans/2026-10-20-test-suite-coordination-plan.md)落实；具体通过范围以实际运行报告为准。目标是在现有测试入口之上补齐范围选择、前置检查、资源协调、失败传播与可信报告；不替代现有测试框架或远端CI。

## 已确认边界

- 覆盖Windows、Android、Web及辅助工具，优先复用现有命令和报告格式，不新增第三方依赖。
- 本轮协调器的实际验收宿主为Windows；Android作为交叉构建目标，不增加Linux原生开发任务。
- 不自动执行ADB、真机安装、摄像头、私有媒体、真实人脸精度、外网推流或许可证验收。
- 不安装/升级全局工具，不改系统环境，不自动重建原node_modules，不下载模型，不删除旧报告或构建树。
- 不自动提交、推送、创建PR或合并。CI或核心配置若需修改，另出可审阅补丁报批；本轮优先不改workflow。

## 现状与缺口

| 现有事实源 | 可复用能力 | 统筹缺口 |
|---|---|---|
| [构建与测试](../guides/build-and-test.md) | 分平台前提、命令和验收边界 | 没有统一可执行入口、输入配置和逐套件汇总 |
| [主CI](../../.github/workflows/ci.yml) | 各job命令、条件和失败门禁 | 本机不能据远端job绿色推断所有非阻断步骤通过 |
| [辅助工具入口](../../scripts/README.md) | Node/Python回归、模型与设备工具分工 | 模型工具前提不齐会出现跳过，不能统一写成完整通过 |
| [文档驱动](../../scripts/run-docs-checks.ps1) | 分别保留文档与卫生扫描退出码 | 当前抑制正文输出，未提供全套调度报告 |
| [E2E驱动](../../scripts/run-web-e2e.ps1) | 端口检查、带插桩Vite、失败传播、作业清理 | 固定安装行为、工具调用及报告位置不适合统一接管；需保持兼容地补充参数 |
| [Cypress启动器](../../web/scripts/e2e-run.mjs) | 子进程环境修正、心跳、旧覆盖率归档 | 当前不透传CLI参数，统筹层不能指定本次JUnit路径 |
| [Vite/Vitest配置](../../web/vite.config.ts) | Vitest JUnit及生产webroot输出 | 默认JUnit为固定路径，必须显式绑定本次运行或验证新鲜性 |

本地cache中的全量驱动曾用于验收，但含宿主绝对路径和历史记录依赖，不能直接作为正式入口。只迁入通用行为，旧文件和证据留存，不按本设计授权删除。

## 方案比较

| 方案 | 优点 | 代价与结论 |
|---|---|---|
| A：Python标准库统筹层，复用既有入口 | 与现有工具及pytest兼容，XML/JSON与进程输出可统一处理，环境路径不入库 | 少量适配与Windows进程资源处理；推荐 |
| B：扩展单份PowerShell总脚本 | Windows命令接入直接 | 选择、报告验证和异常清理易堆进一个脚本；不作为本轮主方案 |
| C：引入通用任务/工作流框架 | 有现成调度功能 | 增加依赖和新配置，超出当前本地串行统筹需要；不采纳 |

## 最小架构

新增 `scripts/run-test-suites.py` CLI，以及 `scripts/testing/` 下职责明确的套件目录、执行器与报告解析模块。采用固定套件注册表，不提供任意命令配置、插件系统、远程执行或分布式调度。

调用关系：范围选择 → 生成执行计划 → 前置检查 → 获取仓库互斥 → 顺序执行 → 校验本次证据 → 输出汇总并释放资源。运行前的计划可单独查看，不启动构建、不访问设备、不生成测试通过结果。

复用现有审计脱敏函数及UTF-8约定。平台命令以参数列表组装；不把用户输入拼成shell代码。Windows批处理所需固定shell边界单独封装并测试含空格路径。

### 套件与顺序

| 套件ID | 内容 | 必需输入或边界 |
|---|---|---|
| `docs` | 文档审计器回归、文档门禁 | Node；门槛H0/M0，不把外链探测缺省写成已验证 |
| `tooling` | 卫生、JNI、action固定检查、Node与Python工具回归 | Node、Python、pytest；合成精度工具缺失时如实记录跳过，不伪造完整覆盖 |
| `windows` | 显式构建选定测试目标，再执行对应CTest | 已配置的独立CMake构建目录；不猜测OpenCV/ncnn/CRT配置，不直接运行未构建目标 |
| `android-mock` | 显式桩APK、模型禁入、Java单测、lint | Java/Android工具链；固定使用--no-daemon；与真实通道分开列项 |
| `android-real` | 真实APK、模型禁入、Java单测、lint | 显式OpenCV及Android ncnn前提，核对双ABI装配；不等于设备或精度验收 |
| `web` | lint、Vitest、build、现有包体检查 | 显式Web工作目录；锁文件及依赖目录兼容，不自动安装；产物路径须核对 |
| `web-e2e` | 受控Vite、Cypress、现有覆盖率门禁 | 同一Web目录、Cypress二进制及空闲5173；无真实后端/设备验收 |

选择多个套件时去重并按上述顺序运行；`web-e2e`可独立选择，但必须完成其服务器/插桩前置检查。单个套件内有依赖的步骤串行执行。默认首个失败即停止，后续步骤/套件标为未运行并给出原因，不增加继续执行或缓存恢复选项。

不将本地组合命名为“全量CI已通过”；汇总列出明确选择范围、未选择项及CI映射。远端非阻断步骤不自动成为本地豁免，已选择的E2E和覆盖率失败必须使本次运行失败。

### CLI与输入

建议接口：

```text
python scripts/run-test-suites.py list
python scripts/run-test-suites.py plan --suite docs --suite tooling
python scripts/run-test-suites.py run --suite docs --suite tooling
```

- `--suite`必填或使用list/plan，不隐式启动所有平台。
- Windows构建目录、Web工作目录、工具可执行路径及Java/Android/OpenCV/ncnn路径通过明确选项或现有环境配置输入；计划显示其来源与前置检查结果，不保存环境变量全集。
- 不读取历史cache/reports中的命令清单作为运行配置，不把本机盘符写进套件注册表。
- 每步设置正的超时，默认按步骤用途分配，可显式覆盖；拒绝0、负数及无效数值。
- 环境调整仅作用于子进程副本；标准流和报告显式UTF-8；临时目录使用本次短路径，兼顾Windows原生测试路径长度。

## 资源和进程所有权

第一版全部串行，在同一仓库根使用Windows进程级独占资源锁。第二个统筹进程快速失败，不能共享当前Gradle目录、CMake树、Web覆盖率或JUnit文件；锁随持有进程退出释放，不通过删除未知锁文件抢占。

该锁仅约束使用本工具的会话，不能保证外部手工构建自动互斥。计划和前置检查应提示实际保护范围，E2E还须检查真实端口占用；发现占用则报告阻塞，不停止占用者。

每次运行持有自身子进程及后台服务所有权。超时/Ctrl+C/错误均须终止本次进程树并关闭资源；只凭进程名称、端口或旧PID不构成清理授权。清理失败须影响最终状态，不写“已清理”。

心跳默认每30秒输出当前套件、步骤、PID及运行时长；心跳只代表存活，测试开始/完成及计数须来自当前证据，不能把Responding或CPU活动当用例进度。

## 报告和可信度

每次在 `cache/reports/test-suites/<唯一运行标识>/` 独占创建目录，拒绝覆盖现有输出；日志、步骤JSON、原始结构化报告和汇总分目录保存。需要短TMP时单独使用短名称。仅生成脱敏日志和必要结果，不保存私有媒体或环境全集。

汇总提供JSON及Markdown，不新增仪表盘。记录：schema版本、run_id、开始/结束时间、HEAD、工作区输入摘要、选择范围、套件/步骤状态、原始退出码、时长、超时/取消/阻塞原因、证据相对路径及摘要。记录运行前后源码绑定变化；不能把代码变化前的结果签署为变化后的源码通过，生成的受跟踪webroot须与输入源码分别处理。

### 结果规则

- 进程退出0且当前步骤要求的结构化证据存在、可解析、属于本次运行并符合原门禁，才判通过。
- JUnit缺失、损坏、零测试或计数矛盾时，测试步骤不得通过；lint/build等命令步骤没有测试计数，不冒充测试用例数。
- pytest、Vitest、Gradle及Cypress按本次JUnit分别统计；CTest报告标注计数单位为“目标”，不混加成内部GoogleTest或自定义用例数。内部计数不可得时明确未知。
- 普通框架跳过按已有语义记录，不自动改为失败；输出跳过数、原因与覆盖限制。`TEST_SKIP_ABSENT`、`TEST_UNVERIFIED`或未提供真实资产不得被汇总为真实精度通过。
- 在新运行专属位置产生报告；固定位置无法重定向时，先记录旧状态再校验本次产出及摘要，拒绝仅凭文件存在或passed字段判通过；不得删除用户旧证据。
- 不合并旧覆盖率计数；沿用现有归档及原门槛，不降低阈值或抑制失败。
- 套件状态区分通过、失败、前置阻塞、超时、取消、未运行及证据不充分；报告覆盖范围与完成程度，不输出未选套件“通过”。

整体退出码：0为已选且已执行步骤满足各自判据（仍须查看跳过/精度边界）；1为测试/门禁失败；2为前置、锁或证据问题；124为超时；130为取消。步骤原始退出码单独保留。中断时尽力留下未完成汇总；无法写报告时固定诊断并非零退出，绝不假造成功报告。

## 现有入口的最小适配

- 为E2E驱动补充可选Web目录、显式工具入口、跳过安装和本次报告位置参数；保留原调用兼容。统筹调用只使用已通过前置检查的依赖，安装/下载另行显式执行，不自动批准依赖脚本。
- 为Cypress启动器补充受控参数透传，使本次JUnit位置可指定；保留已有退出码、心跳、环境隔离和覆盖率归档行为。
- Vitest、pytest、CTest尽量通过命令行指定本次报告；Gradle固定报告目录按新鲜性/所有权规则处理，不为统筹而搬动AGP目录。
- 初期不改workflow、锁文件、模型manifest或覆盖率配置。Windows CI现有tests/scripts目录发现可覆盖新增Python回归；本地适配器能力不能因此冒称已接管整个CI。

## 交付文件范围

| 文件/目录 | 职责 |
|---|---|
| `scripts/run-test-suites.py` | 固定CLI、参数与退出码 |
| `scripts/testing/` | 套件计划/前置、进程与资源所有权、结构化证据和汇总 |
| `scripts/run-web-e2e.ps1`、`web/scripts/e2e-run.mjs`及相关测试 | 参数化接入和兼容回归，仅改统筹必需边界 |
| `tests/scripts/`及受控子进程夹具 | 真实进程行为、报告新鲜性和负向用例 |
| `docs/guides/test-suite-coordination.md`、现有入口与索引 | 用法、套件前提、互斥范围、退出码和验收限制 |

实现前按已批准设计形成小步骤计划；不通过拆出通用工作流框架扩大范围。

## 验收与变异

1. 先写失败回归，再实现；从非仓库当前目录、含空格路径执行list/plan/run均定位正确，不修改系统环境。
2. 受控真实子进程验证成功、非零、启动失败、超时、取消、二次抢锁、占用端口及后代进程清理；不使用真实设备和私有数据。
3. 构造新/旧/损坏/空/计数矛盾JUnit、UNVERIFIED和普通跳过，验证汇总不会假绿，不双计CTest层级。
4. 验证默认失败即停，后续未运行；报告失败不被后续命令成功覆盖，清理失败不被吞掉；合成凭据只在测试内使用，终端和持久化输出均应脱敏。
5. 至少六组行为变异须检出：吞掉非零、接受旧报告、接受无效/零证据、后一成功覆盖前一失败、绕过互斥、漏清本次子进程。保留修复前失败证据与修复后记录。
6. 现有Node/Python/E2E启动器回归通过，文档H0/M0，差异/敏感检查通过。实际运行docs/tooling、Windows选定测试、Android桩通道、Web单测与E2E/覆盖率；真实Android通道仅在明确工具链输入满足时执行并单列结果，否则明确阻塞，不宣称完成真实后端验收。
7. 本轮全部实际验证使用独占新报告；不以旧cache成果代替本次统筹执行，不自动清理旧缓存。不提交、不推送，交付后按用户确认另行进行。
