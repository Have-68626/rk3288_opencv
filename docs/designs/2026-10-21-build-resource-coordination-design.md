# 构建资源契约 B04 设计

本设计沿用已批准的 B04 边界：先统一资源预算、阶段声明和运行指标，默认串行；本轮不启用并行构建，不修改 CI，不提交或推送。目标是让测试统筹与构建统筹使用同一套资源契约，并能说明每步实际占用和冲突原因。

## 方案

在 `scripts/testing/resources.py` 增加最小共享资源模型，由 `scripts/testing/runner.py` 执行。`Step` 声明 CPU 槽位、可选内存上限和独占资源键；测试套件与构建协调器使用同一 CLI 预算与同一报告字段。保留现有 `RepoLock` 作为跨进程仓库级互斥，因此同时最多一个协调器运行；资源键用于拒绝同一执行计划内的冲突声明，并留下可审查的输出/端口归属记录。

| 资源 | 声明及执行规则 |
|---|---|
| CPU | `--cpu-budget` 为显式正整数，默认 2；CMake `--parallel` 与 Gradle `--max-workers` 使用该值。单个阶段声明不得超过预算。此值不从逻辑核心数推算，也不开放跨阶段并行。 |
| 内存 | `--memory-budget-mb` 可选；未指定时明确报告为“仅观测、无上限”，不假造机器安全值。Windows Job 定期采样进程树峰值内存；指定上限后，超过上限即终止本步骤自己的 Job 并将步骤标记为 `resource_limit_exceeded`。 |
| 独占资源 | 阶段声明其构建树、APK/发布输出、Web 输出或固定测试端口。活动步骤持有资源键期间，第二个持有者立即收到 `RESOURCE_BUSY`；步骤结束或异常后释放。不同串行步骤可依次声明同一输出，用于构建与验证交接。跨进程互斥仍由现有仓库级命名锁保护。 |
| 进程与结果 | 保持单步执行；取消只终止当前 Job，失败、超时和资源越限均阻断后续步骤。记录计划并发上限、实际峰值并发进程、峰值 Job 内存、预算值和拒绝/终止原因。 |

内存上限通过 Windows Job 的现有扩展信息采样实现软监控，不设置系统级内存限制。超限检测受采样间隔影响，可能短暂超过配置值；报告注明观测峰值。未配置上限时仍记录峰值，结果不得表述为内存受限运行。

## 修改范围

- `scripts/testing/runner.py`：给 `Step` 加资源声明；在现有 Windows Job 轮询中采集活动进程数和 Job 峰值内存，并在越限时仅终止该 Job。
- `scripts/testing/catalog.py` 与 `scripts/run-test-suites.py`：统一预算参数，给现有步骤登记 CPU 需求、输出/端口资源键和预算；保持七类套件、顺序及门禁不变。
- `scripts/building/coordinator.py` 与 `scripts/run-builds.py`：复用同一预算及资源字段；将硬编码的 CMake/Gradle 并发值改为预算参数；登记每阶段写入路径。
- `scripts/testing/reports.py` 或对应汇总逻辑：在 JSON/Markdown 中呈现预算和观测数据；缺少 Job 计量时显式标为 unavailable，不伪造零值。
- `tests/scripts/`：补充资源超预算、重复输出声明、不同资源可串行通过、Job 峰值指标、越限回收、取消只回收自有进程、失败阻断后续和预算参数兼容回归。

不修改 CMake/Gradle/CI 核心配置、不变更现有测试选择、不开放线程池或多阶段并行、不自动探测“安全”内存预算，也不终止仓库外进程。

## 验收

1. 资源声明超过 CPU/内存预算或重复独占键时，在启动子进程前拒绝，报告包含稳定原因码。
2. 配置 CPU 预算 1、2 时，CMake 与 Gradle 收到相同统一值；执行器的最大同时运行阶段始终为 1。
3. 设置内存上限的合成子进程超过上限后被终止，报告显示实测峰值、上限和原始退出码；未设置上限的报告显示“仅观测”。
4. 超时、取消和越限后仅清理本步骤 Job；不存在自有后代残留，其他进程不受影响。
5. 前一步失败或越限时下游保持 `not_run`；测试统筹与构建统筹的资源字段一致。
6. 运行相关 Python 回归、既有测试统筹回归、构建统筹回归及文档门禁；变异测试证明移除冲突检查、越限处理或失败传播会被检出。

实现前请审阅此设计。确认后再按 TDD 实现；验收期间保持串行，不更改 CI 门槛或远端配置。
